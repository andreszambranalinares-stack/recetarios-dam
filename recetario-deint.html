Formas de dar valor a una propiedad en XAML

Los enumerados se escriben con el nombre del miembro (Center, Bold). Los colores admiten nombre (Red) o hexadecimal (#FF5733, #80FF5733 con alfa). Eso lo hacen convertidores como ColorTypeConverter y LayoutOptionsConverter.

XAML: ventajas y limitaciones (teórico)

XAML (eXtensible Application Markup Language) es un lenguaje basado en XML para crear e inicializar objetos y organizarlos en jerarquías padre-hijo. En MAUI no es obligatorio, pero es lo recomendado, y encaja con MVVM: el XAML es la vista enlazada al ViewModel con data binding.

VentajasLimitaciones
Más conciso y legible que el código equivalenteNo puede contener código: los manejadores de eventos van en el .xaml.cs
La jerarquía XML imita la jerarquía visualNo tiene bucles ni condicionales (un convertidor de binding puede suplir algo)
Herramientas y recarga activa de XAMLNormalmente no crea objetos sin constructor sin parámetros ni llama a métodos

No hay diseñador visual en MAUI: el XAML se escribe a mano y se ve con la recarga activa (Hot Reload). Lo que XAML añade a XML: elementos de propiedad, propiedades adjuntas y extensiones de marcado.

Eventos Clicked paso a paso

Un evento es «algo que pasa» en un control (pulsar un botón, escribir, mover un slider). Para reaccionar se conecta el evento con un método manejador del .xaml.cs. Siempre son los mismos 4 pasos:

  • 1. Ponle nombre a lo que vayas a tocar desde C#. x:Name="lblContador" crea un campo lblContador en el .xaml.cs. El botón solo necesita nombre si lo vas a cambiar (deshabilitarlo, cambiar su texto…).
  • 2. En el XAML, di qué método se ejecuta. Clicked="BtnSumar_Clicked". Al escribir Clicked=" Visual Studio ofrece <Nuevo controlador de eventos> y te crea el método en el .cs.
  • **3. En el .xaml.cs, escribe el método con la firma exacta.** private void BtnSumar_Clicked(object sender, EventArgs e). El nombre tiene que ser idéntico al del XAML.
  • 4. Dentro, lee y cambia propiedades de los controles. lblContador.Text = …, txtNombre.Text, btn.IsEnabled = false…
Parte de la firmaQué es
private voidNo devuelve nada. Con await dentro pasa a ser private async void
BtnSumar_ClickedEl nombre que pusiste en el XAML. Convención: NombreControl_Evento
object senderEl control que lanzó el evento (el botón pulsado). Ver sender
EventArgs eDatos del evento. En Clicked no trae nada; en otros sí (TextChangedEventArgs, ValueChangedEventArgs…). Ver la tabla de eventos

OjoLeer un número de un Entry: double.TryParse(txtCuenta.Text, out double cuenta). El Text de un control siempre es string; para escribir un número: lbl.Text = total.ToString("F2") o $"{total:F2} €".

Qué es y quién es destino u origen

El data binding vincula una propiedad de un objeto con otra de otro objeto, de forma que un cambio en una se refleja solo en la otra. Así sobran los manejadores de eventos que copian valores a mano.

  • Destino (target): el objeto en el que se pone el binding. Casi siempre una vista (Label, Entry…). Su propiedad tiene que ser enlazable (BindableProperty).
  • Origen (source): el objeto al que apunta el binding: otra vista, o un objeto C# (un modelo o un ViewModel).

OjoEl destino es siempre donde escribes {Binding}, aunque los datos vayan del destino al origen.

Modos de enlace

ModoDirección

OneWayToSourceDestino → origen (propiedades de solo lectura, como SelectedItem de ListView)

Clicked con ViewModel: qué va en cada archivo

Con MVVM el Clicked sigue en el .xaml.cs, pero no toca controles: solo llama a un método del ViewModel. Los bindings repintan solos. El recorrido de un clic:

  • 1. Pulsas el botón → se ejecuta Calcular_Clicked en el .xaml.cs.
  • 2. El manejador llama a vm.Calcular().
  • 3. El ViewModel cambia una propiedad (Resultado = …).
  • 4. Fody lanza PropertyChanged("Resultado").
  • 5. El Label con Text="{Binding Resultado}" se entera y se repinta.

Diccionario de recursos (ResourceDictionary): qué es y qué guarda

Un ResourceDictionary es una lista de cosas con nombre (x:Key) que se reutilizan: no solo estilos, también colores, números, márgenes o textos. Se usan con {StaticResource clave} (o {DynamicResource clave}).

TipoEjemploSe usa en

x:Double<x:Double x:Key="Tam">18</x:Double>FontSize, WidthRequest, Spacing
x:Int32<x:Int32 x:Key="N">4</x:Int32>MaxLines, Grid.ColumnSpan
Thickness<Thickness x:Key="M">10,20</Thickness>Margin, Padding
x:String<x:String x:Key="T">Hola</x:String>Text, Placeholder
Style<Style x:Key="..." TargetType="...">Style="{StaticResource ...}"

Herencia de estilos (BasedOn)

  • El hijo añade setters o pisa los del padre.
  • El TargetType del hijo tiene que ser igual al del padre o derivado (View → Label, Button).
  • Solo se hereda de un estilo del mismo nivel o de uno superior (app → página → control).
  • Un implícito puede heredar de un explícito, pero no al revés.

Cambiar estilos en ejecución (DynamicResource)

StaticResource busca la clave una vez. DynamicResource mantiene el vínculo con la clave: si reemplazas lo que hay en el diccionario, se aplica.

Para heredar de un estilo dinámico no sirve BasedOn: se usa BaseResourceKey="estiloAzul".

Clases de estilo (Class + StyleClass): varios estilos a la vez

A diferencia de x:Key, a un control le puedes aplicar varias clases. Si dos clases tocan la misma propiedad, gana la que va después en la lista. Varias clases pueden llamarse igual si su TargetType es distinto.

Teoría para el examen teórico

  • ¿Qué es .NET MAUI? .NET Multi-platform App UI: framework multiplataforma de código abierto para crear apps nativas móviles y de escritorio (Android, iOS, macOS y Windows) con C# y XAML, desde una sola base de código. Es la evolución de Xamarin.Forms, con los controles reescritos para mejorar rendimiento y extensibilidad.
  • ¿Cómo funciona? Unifica las API de cada plataforma en una sola. Por debajo usa .NET para Android, .NET para iOS, .NET para macOS y WinUI 3 (Windows). Todos comparten la BCL (biblioteca de clases base). El runtime es Mono en Android, iOS y macOS, y CoreCLR en Windows. Tu código usa la API de MAUI, que llama a las API nativas; si hace falta, tu código puede llamar a las nativas directamente.
  • Compilación. Android: C# → IL → JIT al arrancar. iOS: AOT completo a código ARM nativo. macOS: Mac Catalyst. Windows: WinUI 3. Para compilar iOS y macOS hace falta un Mac.
  • Qué aporta MAUI. Controles, motor de layouts, varios tipos de página (navegación, cajones/flyout, pestañas), data binding, handlers personalizables, API para el hardware (GPS, acelerómetro, batería, red), gráficos multiplataforma, proyecto único y recarga activa.
  • Proyecto único. Un solo proyecto para todas las plataformas: selección del destino de depuración simplificada, recursos compartidos, un único manifiesto (título, id, versión), un único punto de entrada multiplataforma y acceso a lo específico de cada plataforma en Platforms/.
  • Recarga activa (Hot Reload). De .NET (código C#) y de XAML: ves los cambios con la app en marcha sin recompilar y sin perder el estado de navegación ni los datos.
  • Data binding. Vincula dos propiedades (destino y origen) para que los cambios se propaguen solos y sobren los manejadores de eventos. El destino debe ser una propiedad enlazable de un BindableObject. Se define con BindingContext + SetBinding / {Binding}.
  • INotifyPropertyChanged. Interfaz con un único evento, PropertyChanged, que el ViewModel lanza al cambiar una propiedad para que el binding actualice la vista.
  • Estilos. Style agrupa Setters (Property + Value) para un TargetType. Explícito (x:Key) o implícito (sin clave). Ámbito: control, página o aplicación. Herencia con BasedOn, cambios en ejecución con DynamicResource, varios a la vez con StyleClass.
