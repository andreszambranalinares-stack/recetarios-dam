0.1Qué cambia de navegador a Node

Node es el motor V8 de Chrome sacado del navegador, más módulos para hablar con el sistema operativo. El lenguaje es el mismo; cambia lo que tienes alrededor.

CapaEjemplos¿Existe en Node?
El lenguaje (ECMAScript)const, arrow functions, clases, map, promesas, async/awaitSí, igual
API del navegadordocument, window, alert, localStorageNo: ReferenceError: document is not defined
API de Nodeprocess, require, fs, __dirnameSolo en Node

Por qué Node en un servidor: E/S no bloqueante. Mientras espera a la base de datos o al disco, atiende a otro cliente.

Ojoprocess.argv[0] es la ruta de node y [1] la del script: los tuyos empiezan en la posición 2.

0.2Síncrono, asíncrono y el event loop

Node tiene un solo hilo. Lo síncrono se ejecuta del tirón; lo asíncrono (temporizadores, disco, red) se aparca y su callback vuelve a la cola cuando termina. El event loop solo saca algo de la cola cuando la pila está vacía.

Bloquear el hilo a propósito para verlo:

Ojoen un servidor, un bucle pesado o un readFileSync deja a todos los clientes esperando.

0.2De callback a promesa a async/await

La misma operación en tres estilos. Los callbacks anidados son el «callback hell».

async hace que la función devuelva siempre una promesa. await solo se puede usar dentro de una función async (o arriba del todo en un módulo ESM).

0.2El await olvidado

Ojosi ves Promise { <pending> } o undefined en algo que debería tener datos, casi siempre falta un await.

0.3Módulos CommonJS: require

El sistema original de Node y el que usa el curso con Express. Cada archivo es un módulo con su propio ámbito.

Exportar una sola cosa: module.exports = app; y se importa con const app = require('./app');.

Ojorequire('matematicas') sin ./ busca en node_modules y da «Cannot find module».

0.3Módulos ESM: import

El estándar del lenguaje (el mismo que en Angular). En Node se activa con la extensión .mjs o con "type": "module" en package.json.

0.5Capturar errores con try/catch

Con .then() el equivalente es .catch(error => ...). Para relanzar un error tras registrarlo: throw error; dentro del catch.

Ojoun error asíncrono sin capturar da UnhandledPromiseRejection y en un servidor tumba a todos los clientes.

0.5Promise.all y allSettled

Si una promesa de Promise.all falla, falla todo. allSettled espera a todas y te dice cuál fue bien:

3.4Relación 1:N

Una categoría tiene muchos productos; un producto pertenece a una categoría. La clave ajena (CategoriaId) va en el lado «muchos».

Declara la relación en los dos sentidos: cada uno habilita sus consultas. Las asociaciones en un models/index.js evitan imports circulares.

Opciones útiles: Categoria.hasMany(Producto, { foreignKey: 'categoriaId', onDelete: 'CASCADE' }) y Producto.belongsTo(Categoria, { foreignKey: 'categoriaId' }) (el mismo foreignKey en los dos lados).

3.4Traer datos relacionados: include

Ojono hagas un findByPk de la categoría dentro de un bucle por cada producto (problema N+1: una consulta por fila). include lo hace con un solo JOIN.

3.4Crear comprobando la FK

OjoSQLite no comprueba las claves ajenas igual de estricto que MySQL: valida tú que la categoría existe antes de crear.

Calcular el total: completo.Productos.reduce((s, p) => s + p.precio * p.PedidoProducto.cantidad, 0).

3.6Transacción manual

Varias escrituras que deben salir todas o ninguna. Sin transacción, si falla la tercera línea te queda un pedido a medias.

Ojohay que pasar { transaction: t } a cada operación. La que no lo lleve va por fuera y no se deshace.

3.6Transacción gestionada

La forma recomendada: pasas una función a sequelize.transaction(). Si termina bien hace commit; si algo lanza, rollback solo.

Para comprobar que el rollback funciona: manda un pedido con un id de producto que no existe en la última línea y mira que no se ha creado el pedido ni ha bajado el stock de las primeras.

4.3El _id y el CastError

Un _id válido tiene 24 caracteres hexadecimales. Si llega /productos/123, Mongoose no puede convertirlo y lanza CastError: es un 400, no un 404 ni un 500.

Comprobarlo antes, sin consultar: mongoose.Types.ObjectId.isValid(req.params.id) (o mongoose.isValidObjectId(id)).

Ojoaquí no hay que hacer Number(req.params.id): el _id es un texto.

4.4Documentos embebidos

Los datos relacionados viven dentro del mismo documento. Una sola lectura lo trae todo, sin joins.

Sin cargar el documento: Post.findByIdAndUpdate(id, { $push: { comentarios: datos } }, { new: true }) y { $pull: { comentarios: { _id: cid } } }.

4.4Referencias y populate

Colecciones separadas unidas por un ObjectId, como una clave ajena. populate sustituye el id por el documento completo.

Ojoel ref es el nombre del modelo ('Autor'), no el de la colección (autors). Si no coincide da «Schema hasn't been registered for model».

4.4¿Embeber o referenciar?

Embeber si…Referenciar si…
Siempre se leen junto al padre (comentarios de un post)Se consultan solos o desde varios sitios (autores)
Pertenecen solo a ese padreSe comparten entre muchos documentos
Son pocos y no crecen sin límitePueden crecer mucho (el documento tiene un máximo de 16 MB)
Se actualizan poco por separadoCambian a menudo y no quieres repetir el cambio en muchos sitios

Regla rápida: relación 1:pocos que se lee junta → embeber; 1:muchos o N:M → referenciar.

4.5Proyecciones

Pedir solo los campos que hacen falta (como attributes en Sequelize).

Ojono mezcles incluir y excluir en la misma proyección ('nombre -precio' da error). La única excepción es _id.

4.5Agregaciones: aggregate

Un pipeline: un array de etapas por las que pasan los documentos en orden. Sirve para cálculos que find no hace (medias, totales por grupo).

EtapaQué haceSQL parecido
$matchFiltra documentosWHERE
$groupAgrupa y calcula ($sum, $avg, $min, $max)GROUP BY
$sortOrdenaORDER BY
$projectElige o transforma camposSELECT a, b

Ojopon $match lo antes posible: filtra antes de agrupar y el pipeline procesa menos documentos.

CambiaSequelizeMongoose
Idid numérico, Number()_id texto, isValidObjectId
Relación 1:NhasMany + belongsToref en el hijo (o embebido)
Traer relacionadosincludepopulate
Crear tablassync() o migracionesNada: la colección aparece sola
Error de formato de id—CastError → 400
TransaccionesSencillas (3.6)Requieren replica set; se evitan embebiendo

Cómo usarlo

Lee el problema, escríbelo sin mirar (en papel o en un archivo vacío), pruébalo con node o Postman y luego compara con la receta enlazada. Lo que falles, repítelo otro día.

Bloque 0

  • Script que muestre la versión de Node, la plataforma, la carpeta actual y los argumentos que le pases.Receta: Ejecutar un script y usar process
  • Di en qué orden salen un console.log, un setTimeout(…, 0) y un Promise.resolve().then(…), y por qué.Receta: Event loop
  • Convierte consultaLenta(valor, callback) en una función que devuelva una promesa y úsala con async/await.Receta: De callback a promesa a async/await
  • Módulo matematicas.js con sumar y restar en CommonJS; luego pásalo a ESM.Receta: CommonJS y ESM
  • Guarda una línea de log con la fecha en logs/app.log cada vez que se ejecute el script, y luego muestra el archivo entero.Receta: fs/promises y path
  • Servidor http sin Express con / en texto, /tareas leyendo un JSON del disco y 404 para lo demás.Receta: Servidor con http a pelo
  • Tres llamadas simuladas de 300 ms: mide el tiempo en serie y con Promise.all. Después haz que una falle y usa allSettled.Receta: Promise.all y allSettled

Bloque 1

  • Pasa el servidor http anterior a Express.Receta: Primer servidor Express
  • Separa el proyecto en src/app.js e index.js, con el puerto en .env y scripts start y dev.Receta: app.js e index.js, dotenv y nodemon
  • Rediseña en REST: GET /obtenerTodosLosLibros, GET /obtenerLibroPorId?id=3, POST /nuevoLibro, GET /borrarLibro/5.Receta: Diseñar rutas REST
  • CRUD completo de libros en memoria con 200, 201, 204, 400 y 404 donde toque.Receta: CRUD completo en memoria
  • GET /productos/:id?moneda=usd que use el parámetro y el query a la vez.Receta: Leer la petición
  • Middleware que registre método, URL, código de respuesta y milisegundos de cada petición.Receta: Qué es un middleware
  • Middleware que corte con 401 si no llega la cabecera x-api-key correcta, solo en /admin.Receta: Middleware que corta y dónde se aplica
  • Middleware que limpie el título, borre el id del body y añada creadoEn antes de crear.Receta: Middleware que enriquece req

Bloque 2

  • Saca las rutas de tareas y usuarios a dos routers y móntalos bajo /api/v1.Receta: express.Router y prefijo
  • Valida a mano que titulo sea texto y precio un número positivo; responde 400 con un mensaje claro.Receta: Validar el body a mano
  • GET /productos?pagina=2&limite=5 que devuelva { pagina, limite, total, datos }.Receta: Paginación
  • Arregla un app.js donde el router va antes de express.json() y explica qué pasaba.Receta: req.body undefined y orden
  • Manejador de errores centralizado, un 404 para rutas inexistentes y una clase ErrorHTTP usada en dos rutas.Receta: Errores, 404 y ErrorHTTP
  • Esquema Zod de producto (nombre mínimo 2, precio positivo, stock entero ≥ 0) y middleware validar(esquema) reutilizado en dos recursos.Receta: Zod y validar(esquema)
  • Habilita CORS solo para http://localhost:4200.Receta: CORS
  • Subida de imagen de producto con multer: solo JPG/PNG, máximo 2 MB, conservando la extensión.Receta: multer y límites

Bloque 3

  • Conecta Sequelize a SQLite, comprueba la conexión con authenticate() y activa el log del SQL.Receta: Instalar y conectar y ver el SQL
  • Modelo Producto (nombre obligatorio, precio ≥ 0, stock por defecto 0) y explica la diferencia entre sync(), alter y force.Receta: Definir un modelo y sync
  • Pasa el CRUD de productos del array a Sequelize sin tocar la validación ni el manejador de errores.Receta: El CRUD dentro de las rutas
  • GET /productos?min=20&orden=precio&dir=DESC&pagina=1&limite=5 con Op y findAndCountAll.Receta: where y Op y paginar
  • Relación 1:N Categoria–Producto; GET /productos con su categoría y GET /categorias/:id/productos.Receta: Relación 1:N e include
  • Al crear un producto, responde 400 si la categoría no existe.Receta: Crear comprobando la FK
  • Relación N:M Pedido–Producto con cantidad; GET /pedidos/:id con productos, cantidades y total.Receta: N:M y consultar
  • POST /pedidos con varias líneas en una transacción que descuente stock; demuestra que si falla una línea no se guarda nada.Receta: Transacción gestionada
  • Reorganiza el recurso productos en ruta, controlador y servicio, y arranca el servidor solo cuando la base de datos esté lista.Receta: Capas y arrancar

Bloque 4

  • Explica con un ejemplo cuándo elegirías SQL y cuándo MongoDB para guardar pedidos, comentarios de un blog y logs.Receta: SQL o MongoDB
  • Conecta Express a MongoDB con la URI en .env y no abras el puerto hasta que la conexión esté lista.Receta: Instalar y conectar
  • Esquema Producto: nombre obligatorio, precio ≥ 0, categoría de una lista y timestamps. Prueba a crear uno inválido y muestra los mensajes.Receta: Esquema y validaciones
  • CRUD completo de productos con Mongoose: 201, 204, 404 si no existe y 400 si el id no tiene formato válido.Receta: El CRUD dentro de las rutas y CastError
  • GET /productos?min=20&orden=precio&dir=desc&pagina=2&limite=5 con $gte, sort, skip y limit.Receta: Operadores $ y paginar
  • Modelo Post con comentarios embebidos y rutas para añadir y borrar un comentario.Receta: Documentos embebidos
  • Relación Autor–Post por referencia; GET /posts con el nombre del autor usando populate.Receta: Referencias y populate
  • Lista de productos con solo nombre y precio.Receta: Proyecciones
  • Agregación: total y precio medio por categoría de los productos de más de 30 €, ordenado por total.Receta: aggregate
  • Migra el servicio de productos con categoría del bloque 3 a Mongoose sin tocar rutas ni controladores.Receta: Migrar un recurso
