Crear un componente

Plantilla y estilos dentro del .ts en vez de en archivos aparte:

Usar un componente dentro de otro

Dos pasos: meter la clase en imports del padre y poner su etiqueta (el selector) en el HTML del padre.

Ojosin el imports sale «'app-tarjeta-producto' is not a known element».

Mostrar un valor: interpolación {{ }}

Dentro de {{ }} puedes poner expresiones y llamar a métodos. No se permiten asignaciones ({{ nombre = 'x' }}) ni bucles.

Dar valor a una propiedad: property binding [ ]

Dentro de [ ]="..." todo es TypeScript: las variables van sin comillas y los textos con comillas simples ('Zapatilla').

Ojo[disabled]="'sinStock'" es el texto «sinStock», no la propiedad.

Clase o estilo según una condición

No hace falta importar nada. Para varias clases a la vez: ngClass.

Reaccionar a un clic: event binding ( )

Otros eventos: (input), (change), (submit), (mouseenter), (keyup.enter).

Leer lo que escribe el usuario con $event

$event es el evento del navegador. El texto está en target.value, pero hay que decirle a TypeScript que es un input (as HTMLInputElement).

Enlace en las dos direcciones: [(ngModel)]

Lo que escribes cambia termino, y si cambias termino desde el código cambia el input. Es lo mismo que [ngModel]="termino" (ngModelChange)="termino = $event".

Ojosin FormsModule en imports no funciona.

Las cuatro formas de binding, juntas

SintaxisNombreDirección
{{ valor }}InterpolaciónTS → texto en pantalla
[prop]="valor"Property bindingTS → propiedad del elemento
(evento)="metodo()"Event bindingelemento → TS
[(ngModel)]="valor"Two-way bindinglas dos (necesita FormsModule)

Hacer algo al crearse el componente: ngOnInit

Se ejecuta una vez cada vez que se crea ese componente, no al arrancar la app. Es el sitio para cargar datos.

Limpiar al quitarse: ngOnDestroy

Se ejecuta cuando el componente desaparece: un @if que pasa a false, cambiar de ruta… Si no paras el setInterval, sigue funcionando por detrás.

Reaccionar cuando cambia un @Input: ngOnChanges

Solo salta cuando el padre cambia un @Input. El orden es ngOnChanges → ngOnInit → … → ngOnDestroy.

@if, @for y @switch son parte de la plantilla: no se importan.

Recorrer una lista: @for

track es obligatorio. Si no hay id, usa track $index. @empty se muestra cuando la lista está vacía.

Variables que tienes dentro: $index, $first, $last, $even, $odd, $count.

Varias opciones: @switch

Varias clases a la vez: ngClass

La clave es el nombre de la clase y el valor, la condición. Con una sola clase basta con [class.agotado]="...".

Varios estilos a la vez: ngStyle

Los nombres con guion van entre comillas: 'font-weight', 'background-color'.

Pasar datos del padre al hijo: @Input

Los datos bajan con [ ]. El padre tiene que importar al hijo en imports.

input(): la versión con señales

En la plantilla del hijo se leen con paréntesis: nombre(). El padre lo usa exactamente igual que con @Input.

Avisar al padre desde el hijo: @Output

Los eventos suben con ( ). Lo que pasas a emit() le llega al padre como $event.

output(): la versión con señales

El padre lo escucha igual: (anadido)="metodo($event)".

Usar un servicio en un componente

Si lo vas a usar en la plantilla, déjalo público (sin private).

Ojoel servicio no va en imports del componente. Se pide con inject().

Ojono hagas new CarritoService(): crearías una copia propia y no compartirías los datos.

Pedirlo por constructor (forma clásica)

inject() es la forma recomendada. Con @Service() el constructor no vale para pedir dependencias (error NG2028): usa inject().

Proteger una ruta con un guard

Formulario template-driven

#f="ngForm" es una variable que apunta al formulario entero: f.value, f.valid, f.invalid. Se envía con (ngSubmit) en el <form>, no con (click) en el botón.

Ojocada input con ngModel dentro de un <form> necesita name. Sin él, Angular da error.

Agrupar campos: ngModelGroup

f.value queda como { nombre: '...', direccion: { calle: '...', ciudad: '...' } }.

Validar un formulario template-driven

Los validadores se ponen como atributos: required, minlength="3", maxlength="20", email, pattern="[0-9]+". Con [disabled]="f.invalid" no se puede enviar si algo falla.

Mensajes de error por campo (template-driven)

#emailCtrl="ngModel" apunta a ese campo. errors tiene una clave por cada validador que falla: 'required', 'email', 'minlength'…

Se comprueba touched para no mostrar el error antes de que el usuario haya escrito.

Validador personalizado

Devuelve null si es válido y un objeto { nombreDelError: true } si no. Esa clave es la que lees en errors?.['...']. Al usarlo se llama con paréntesis: soloLetrasValidator().

Cómo usarlo

Para practicar para el examen escrito. Lee el problema, escríbelo en papel sin mirar y luego compara con la receta enlazada. Lo que falles, repítelo otro día.

Bloque 1

  • Crea un componente tarjeta-producto y píntalo dos veces dentro de app.html.Receta: Usar un componente dentro de otro
  • Un componente con nombre, agotado y cantidad: muestra el nombre, deshabilita un botón si está agotado, llama a comprar() al pulsarlo y enlaza un input a cantidad en las dos direcciones.Receta: Las cuatro formas de binding
  • Sin ngModel: guarda en texto lo que se escribe en un input y muéstralo debajo.Receta: Leer lo que escribe el usuario
  • Un cronómetro que empiece al crearse el componente y se pare al quitarlo.Receta: ngOnDestroy

Bloque 2

  • Pinta una lista de tareas con un mensaje si está vacía y numera cada una.Receta: @for
  • Muestra un texto distinto según estado sea 'pendiente', 'enviado' u otro.Receta: @switch
  • Pon la clase agotado si stock === 0 y la clase oferta si enOferta.Receta: ngClass
  • Directiva appResaltado que cambie el fondo al pasar el ratón, con el color pasado desde fuera.Receta: Crear una directiva propia
  • Muestra un precio en euros y una fecha como 21/11/2026.Receta: Pipes integrados
  • Pipe truncar que recorte un texto a N caracteres (50 por defecto) y añada ....Receta: Crear un pipe propio
  • El padre pasa nombre y precio a una tarjeta; la tarjeta tiene un botón «Añadir» que avisa al padre con el nombre.Receta: @Input y @Output

Bloque 3

  • Crea un CarritoService con una lista, un método para añadir y un total. Muestra el total en app.html.Receta: Crear un servicio y usarlo
  • Dos componentes hermanos: uno añade tareas y el otro las lista.Receta: Compartir datos entre hermanos
  • Explica qué pasa si pones el servicio en providers de cada componente.Receta: Una instancia propia

Bloque 4

  • App con Inicio, Catálogo, un menú con el enlace activo resaltado y una página 404.Receta: Definir las rutas y menú
  • Lista de productos que enlaza a /producto/:id; el detalle lee el id y busca el producto.Receta: Ruta con parámetro y leerlo
  • Dentro de /cuenta, dos pestañas: /cuenta/perfil y /cuenta/pedidos.Receta: Rutas hijas
  • Al pulsar «Guardar», vuelve al catálogo desde código.Receta: Navegar desde código
  • Solo se entra en /cuenta con sesión iniciada; si no, a /login.Receta: Guard
  • Haz que /admin se descargue solo al visitarla.Receta: Lazy loading

Bloque 5

  • Formulario de contacto con nombre, email y mensaje (template-driven) que muestre los valores al enviar.Receta: Template-driven
  • Al anterior: nombre obligatorio y mínimo 3, email válido, botón deshabilitado y mensajes del email solo si se ha tocado.Receta: Validar y mensajes
  • El mismo formulario, reactivo con FormBuilder.Receta: FormBuilder
  • Validador passwordSeguraValidator(): mínimo 8 caracteres, una mayúscula y un número; error { passwordInsegura: true }.Receta: Validador personalizado
  • Perfil con nombre obligatorio y una lista de habilidades: botones para añadir y quitar, y el total fuera del formulario.Receta: FormArray
